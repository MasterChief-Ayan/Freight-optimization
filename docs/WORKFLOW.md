# WORKFLOW — how changes are saved, versioned and branched

Repository: **github.com/MasterChief-Ayan/Freight-optimization** (private).
GitHub is the single source of truth for code and results. The MTP project on claude.ai holds the
two context docs (`MTP_PROJECT_STORY.md`, `MTP_CODEBASE.md`), refreshed at the end of every session.

## The three places, and what lives where
| Place | Holds | Updated by |
|---|---|---|
| GitHub repo | code, data, results (charts/CSVs), docs, full history | every Claude Code session commits and pushes |
| claude.ai MTP project | dated folders, each with `MTP_PROJECT_STORY.md`, `MTP_CODEBASE.md`, `MTP_WORKFLOW.md` (context for any new chat) | Claude, at the end of each session |
| GitHub repo, `data/raw/` | ER RR register 2022–26 (not confidential) | add new monthly files there and commit |

## Every working session (Claude Code, attached to the MTP project)
1. **Start:** say "continue the MTP work". Claude reads the docs in the **latest dated folder** of the
   MTP project (e.g. `22October2026/`), attaches the repo (it clones it), and creates a branch for the task.
2. **Work:** small commits with clear messages. Every result is regenerated by code, never edited by hand.
3. **Check:** `bash run_all.sh quick` (57 model checks) and `python tools/verify_extensions.py`
   (23 checks) must pass, 80 in total. A refactor must also give `ALL IDENTICAL` in `tools/compare_outputs.py`.
4. **Save:** push the branch, open a pull request into `main`, merge once checks pass.
5. **Close:** update `docs/PROJECT_STORY.md` / `docs/CODEBASE.md` / `docs/WORKFLOW.md`, and copy all three
   to a new dated folder in the MTP project (`<D><Month><YYYY>/MTP_*.md`, e.g. `5November2026/`).
   Older dated folders stay as history; the newest one is the current state.

Nothing is lost between sessions: the repo keeps every version, and the project keeps the context.

## Commit and push rules (learned 22-Oct-2026)
- **Author = Ayan Ahmed <ayanahmed2003786@gmail.com>** on every commit; no AI co-author or session
  trailers in messages.
- Cloud sessions reject a single push of ~35 MB+ (HTTP 403). Push large data in parts (e.g. one commit
  per year of data, pushed one at a time).
- Cloud sessions cannot push tags; create milestone tags on GitHub as Releases (Releases → Draft a new
  release → tag name → target commit).
- Rewriting published history (force-push) only with Ayan's explicit approval.

## Branches
| Branch | Purpose | Rule |
|---|---|---|
| `main` | verified state; what the thesis quotes | change only by merging a branch whose checks pass |
| `feat/<topic>` | new capability, e.g. `feat/unloading-side`, `feat/scaling` | branch from `main`, merge back |
| `exp/<topic>` | exploratory what-if that may be thrown away, e.g. `exp/time-indexed-bound` | merge only if it becomes a result |
| `data/<source>` | wiring in a new field dataset (raw files + decoding code) | merge after the decoding checks pass |
| `thesis` | LaTeX thesis sources (if kept in this repo) | long-lived; merge `main` into it for new figures |

## Commands (if you ever do it yourself)
```bash
git clone https://github.com/MasterChief-Ayan/Freight-optimization.git
cd Freight-optimization
git switch -c feat/my-change           # new branch
# ... edit, then:
bash run_all.sh quick                   # checks
git add -A && git commit -m "what changed and why"
git push -u origin feat/my-change       # then open a pull request on GitHub
git switch main && git pull             # after merging
git checkout v1.0-midterm-model         # look at an old milestone (read-only)
```

## Never
- commit `data/processed/` (regenerable cache; `.gitignore` blocks it) or any dataset the owner calls confidential;
- edit a number in `results/` by hand — change the code and re-run;
- merge into `main` with a failing check;
- add AI co-author or session trailers (`Co-Authored-By: …`, `Claude-Session: …`) to commit
  messages, or commit as any author other than Ayan Ahmed (owner's decision, 22-Oct-2026).
